# Jira Ticket Guidelines

## Purpose

These guidelines define the recommended structure and quality expectations for product requirement tickets.

## Required Ticket Sections

A standard user story should contain:

1. User Story
2. Acceptance Criteria
3. Edge Cases
4. Metadata

## User Story Convention

Use the standard Agile structure:

As a [user persona], I want to [action], so that [benefit].

The story should describe the user's need and desired outcome rather than technical implementation.

## Acceptance Criteria

Acceptance criteria must be:

- Specific
- Testable
- Functional
- Clearly related to the user story
- Easy for product, QA, and engineering teams to understand

At least four acceptance criteria should normally be provided.

## Edge Cases

Identify realistic situations that could cause an alternative flow.

Examples include:

- Invalid user input
- Missing required information
- Expired information
- Duplicate actions
- Service interruption
- Unauthorized access
- Boundary conditions

At least three edge cases should normally be documented.

## Priority

Priority should be categorized as:

- High
- Medium
- Low

The priority should consider:

- User impact
- Business value
- Urgency
- Risk
- Relative implementation effort

## Scope

A ticket should focus on the requested functionality.

Unrelated features should not be added to the ticket.

## Writing Style

Tickets should be:

- Clear
- Concise
- Professional
- User-focused
- Functional
- Easy to copy into a ticketing system

Avoid unnecessary technical implementation details unless specifically required by the ticketing context.
